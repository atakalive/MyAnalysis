# ミーティング共有

[← README に戻る](../README_ja.md)

自分の解析タブ（図）とチャットを、離れた相手のブラウザへライブで共有する。相手もチャットで AI に指示できる。

> [!WARNING]
> - **参加リンク（招待トークン）を持つ人は誰でも、あなたの PC の AI エージェントに承認なしで指示できる。** 既定の権限設定では、あなたのユーザー権限でできること全て（シェルコマンドの実行、ファイルの読み書き・削除、`.env` の API キーの読み取り、別のデータセットを開くことなど）が可能。信頼できる相手にだけ、会議ごとに渡すこと。
> - 既定では、**開いているデータセットの**タブ（解析タブ・図ビューア・画像ビューア）とチャットが共有される。データセット未設定のチャット・タブと、閉じたデータセットのチャットは共有されない。チャットは**開始前の過去の履歴も含む**。ツール実行の内容（コマンド・パス・出力）も相手に届く。開いているデータセットの名前は常に見える。参加者は開いているデータセットに新しいチャットを作れる（そのデータセットのチャットを全部外していても）。開いていないデータセットには作れない（参加者の画面に「新規チャットが作成されませんでした。」と出る）。
> - 非公開にしたいチャット・タブは、開始前でも共有中でもチェックを外せる。外したものは「停止」→「開始」しても、コマンドから開始しても、閉じて開き直しても外れたまま（アプリを終了するまで覚えている）。データセットを閉じると、そのチャットとタブは共有から外れる。閉じた時点で公開範囲を送り直すが、それがリレーに反映されるまでは、まだ取得していない履歴・画像も取得され得る（通信に失敗したときは反映が遅れる）。参加者が既に取得した分は取り消せない。開き直すと、チェックを外していない限りまた共有される。共有中に開いたデータセットのチャットも、「新規セッションを自動共有」が ON なら共有される（OFF ならチェックを付けるまで共有されない）ので、外すなら開いた後にチェックを外す。会議中、または共有ウィンドウを一度でも開いた後に、データセットが開いていない間に発言したチャットは、後からデータセットが付いても自動では共有されない（共有ウィンドウでチェックを付ける）。共有ウィンドウを開かずに会議の前に発言し、後からデータセットが付いたチャットは、開始時に共有される（外すなら開始前に共有ウィンドウでチェックを外す）。データセット未設定の空のチャットは、データセットを開いた状態で最初に送信した時点で新しいチャットとして扱われる（「新規セッションを自動共有」が OFF なら共有されない）。チェックを外した（共有しないと決めた）チャットを分岐（メッセージの編集を含む）した新しいチャットも、共有されない（アーカイブ・削除しただけの元チャットや、「新規セッションを自動共有」が OFF で共有されていないだけの元チャットからの分岐は、普通の新しいチャットとして扱う）。チャット検索（Ctrl+F）の結果タブも、ほかのチャット（共有しないチャットを含む）の抜粋を載せるので共有しない。こうして規則で共有されなかったチャットは、共有ウィンドウでチェックを付けるまで、「停止」→「開始」しても共有されない（アプリを終了するまで覚えている）。公開範囲は参加者の画面に出す範囲で、アクセス制御ではない。参加者はエージェントに頼めば、外したチャット（保存ファイルやエンジンの会話記録）や開いていないデータセットも読める（上の WARNING のとおり）。
> - 通信は Cloudflare を経由する（Cloudflare 上で暗号化が解かれる）。LAN リンクは暗号化されない http で、共有中はリレーが全ネットワークインターフェースで待ち受ける（トークンも平文で流れる）。
> - 相手を個別に退出させることはできない。「停止」→「開始」で新しいリンクになり、古いリンクは全員分が無効になる。参加者名は自己申告。参加者の発言と AI の応答は、あなたのチャット履歴に保存される。「停止」・期限切れの時点で、まだ実行されていない参加者の発言は捨てられる（実行中の応答は最後まで続く）。
> - 参加者の発言は 1 件 16,000 文字まで（名前などを含めた送信全体は 128 KiB まで）。送信が速すぎると一時的に断られる（参加者の画面では「送信失敗」になり、再送できる）。
> - 「ミーティング共有」ウィンドウを閉じても共有は止まらない。止めるには **停止** を押すか、期限切れを待つか、アプリを終了する。

## 事前準備（1 回だけ）

1. `.env` に `RELAY_ADMIN_KEY` を設定する（任意の長い秘密文字列。例: `python -c "import secrets; print(secrets.token_urlsafe(32))"` の出力）。空なら共有機能が無効になるだけ。
2. 外部から参加してもらうには、Cloudflare の named tunnel が必要。Cloudflare の無料アカウントと、ネームサーバーを Cloudflare に向けた**自分のドメイン**が要る（trycloudflare の一時トンネルには対応していない）。
   - cloudflared を入れる（Windows: `winget install cloudflare.cloudflared`）。
   - `cloudflared tunnel login` → `cloudflared tunnel create <トンネル名>` → `cloudflared tunnel route dns <トンネル名> <ホスト名>`
   - `.env` に `CLOUDFLARE_TUNNEL_NAME=<トンネル名>` と `CLOUDFLARE_TUNNEL_HOSTNAME=<ホスト名>`（任意で `CLOUDFLARED_BIN`, `CLOUDFLARE_TUNNEL_CRED`）。
3. `.env` は起動時に一度だけ読むので、編集したらアプリを再起動する。

詳しい手順（別の PC でトンネルを使う方法、LAN 公開時の注意など）は [relay-worker/README.md](../relay-worker/README.md)。

## 共有を始める

1. **表示 → ミーティング共有…** を開き、「有効期間（最大24h）」（既定 3 時間）と「表示名」を決めて **開始**。
2. 状態が「● トンネル起動中…」→「● 共有中」になったら、「公開チャットセッション（全dataset）」「公開解析タブ」のチェックで公開範囲を調整する。「新規セッションを自動共有」で、開始後に作ったチャットの扱いを決める。
3. **参加リンクコピー**（`https://<ホスト名>/#token=…`）で相手に渡す。**トークンコピー** の場合、相手は `https://<ホスト名>/` を開いてトークンを貼る。
4. 「参加者」「ログ」で様子を確認し、終わったら **停止**。

参加者はリンクを開いて表示名を入れ、**Join / 入室** を押す。できること: データセットの切り替え（「ホストに追従」も可）、タブの図の閲覧（静止画・拡大・コピー・ダウンロード）、共有チャットの閲覧（過去の履歴も取得できる）と送信、新しいチャットの作成。他の参加者の発言も見える。

## LAN リンク（任意）

会場のネットワークがトンネルのホスト名を解決できない場合に、ホスト PC へ LAN で直接つなぐ 2 本目のリンクを出せる。

- 共有ウィンドウで、**開始する前に**「LAN リンクも出す（直結・http）」を ON にし、「ホスト IP」を確認する（自動検出値は必ず確かめる）。開始後に LAN を追加するには「停止」→「開始」（新しいリンクになる）。ホスト IP が空のまま開始すると、環境変数 `RELAY_LAN_HOST`（`.env` に書いた値を含む）があればその値を使い、それも空なら LAN リンクなしで開始し、ログ欄に知らせる。
- **LAN 参加リンクコピー** でリンク全体を渡す（トークン単体では使えない）。
- `.env` の `RELAY_LAN_HOST`（IP の初期値）、`RELAY_LAN_PORT`（固定ポート。使用中なら開始に失敗する）。
- Windows ファイアウォールでの許可、参加者側ブラウザの「HTTPS のみ」モードの解除が必要な場合がある。
- 外部リンクが失敗しても、「外部リンク使用不可（LAN リンクのみ有効）」として LAN だけで続けられる。

## コマンドから操作する

```bash
python -m llm_bridge window meeting-start [lan=true] [ttl_sec=3600..86400] --wait   # 多くは "starting" が返る
python -m llm_bridge window meeting-token --wait      # トークン（または starting / tunnel_failed / idle 等の状態）
python -m llm_bridge window meeting-lan-link --wait   # LAN の参加リンク（lan=true には RELAY_LAN_HOST が必要）
python -m llm_bridge window meeting-stop
```

参加リンクは `https://<CLOUDFLARE_TUNNEL_HOSTNAME>/#token=<トークン>`。`ttl_sec` の既定は 10800（3 時間）で、範囲外の値は丸められる。CLI から開始しても、共有ウィンドウで外したチャット・タブは外れたまま。`RELAY_ADMIN_KEY` が未設定なら `meeting-start` はエラーで止まる。

## うまくいかないとき

| 表示 | 対処 |
|---|---|
| 「ミーティング共有を使うには .env に RELAY_ADMIN_KEY を設定してください。」 | `.env` に設定して再起動 |
| 「トンネル起動に失敗しました」 | 共有ウィンドウのログ欄に「原因: …」が出る。よくある原因は `CLOUDFLARE_TUNNEL_NAME` / `CLOUDFLARE_TUNNEL_HOSTNAME` が未設定（または編集後に再起動していない）、cloudflared が PATH に無い。それ以外は `cloudflared tunnel run <トンネル名>` を手で実行してエラーを見る。LAN リンクを使っていなければ共有は停止されるので、直してから再度 **開始** |
| 参加者に Cloudflare のエラー 1033 | ホストが共有していない（停止・期限切れ・アプリ終了）か、`route dns` とホスト名の不一致 |
| 参加者側「ミーティングが終了しました」 | 新しいリンクが必要 |
| 回線が細い | `.env` の `RELAY_VIEW_MAX_MP`（送る図の最大画素数。既定 8 メガピクセル）を 2〜4 程度に下げて再起動する（数値でない・0 以下の値は既定の 8 として扱う） |
